## VirtualList 浏览器最大滚动高度限制修复

- 路径：`apps/new-world/src/views/VirtualList/components/VirtualList.vue`
- 问题：总高度 `list.length * itemHeight` 超过浏览器单容器滚动上限（Chrome≈33,554,432 / Firefox≈17,895,698）时，撑高元素被裁剪，滚动条拖到底也到不了最后一条（如 335545 条被截）。
- 旧代码 `ratio1`/`totalHeight1` 存在循环依赖且 `scrollHeight` 写死常量，实际无效。
- 修复：用 `maxScrollHeight`(默认 15,000,000，可配) 限制 phantom 高度；滚动比例用 `(totalHeight - H)/(phantomHeight - H)`（减容器高 H 是关键，否则底部 (scale-1)*H 不可达），`realTop = scrollTop * ratio`，`offsetY = scrollTop + startIndex*itemHeight - realTop`。底部可达性已用 node 模拟验证（含 335545）。

## VirtualList 分段滚动方案（另一实现，新建文件，未改原文件）

- 新文件：`apps/new-world/src/views/VirtualList/components/SegmentedVirtualList.vue`（组件）+ `apps/new-world/src/views/VirtualList/SegmentedDemo.vue`（演示，100万条/每段10万）。
- 思路：按 `segmentSize`(默认10万)分段，单段高度=segmentSize*itemHeight ≤ maxScrollHeight(默认15,000,000，可配)，单段永不超过浏览器滚动上限，无需缩放。
- 跨段：向下滚到本段底部→自动 `currentSegment++` 并同步重置 `scrollTop/el.scrollTop=0`（滚动条回顶，开始下一段）；最后一段到底即真实终点。向上跨段用 `wheel`(`deltaY<0 && scrollTop<=0`)跳到上一段底部，用 `suppressAdvance` 标记屏蔽程序化滚动触发的 scroll 事件（防误判到底），60ms 兜底清除。
- `effectiveSegmentSize = min(segmentSize, floor(maxScrollHeight/itemHeight))` 自动 clamp，大 itemHeight 也不超限（验证 itemHeight=300 时 clamp 到5万，单段=15M）。
- 右下角 badge 显示「第 X/Y 段 · 本段范围」便于验证。

## VirtualList 不定高度分段方案（第三实现，新建文件，未改原文件）

- 新文件：`apps/new-world/src/views/VirtualList/components/DynamicSegmentedVirtualList.vue` + `apps/new-world/src/views/VirtualList/DynamicSegmentedDemo.vue`（100万条，高度 40~129px 不等）。
- 背景：每个 item 高度不同，不能再用 count×固定高。改用 ResizeObserver 测量每个渲染 item 的真实高度；用 Fenwick 树(BIT) 维护累计偏移量，O(logN) 更新/查询（支撑百万级）。
- 分段：按累计像素高度切段，`SEG_TARGET = maxScrollHeight*0.9`，每段高度 ≤ 上限；单段永不被裁。BIT.findIndex(pos) 由全局位置反查 item 下标。
- 跨段：向下滚到本段底部→`globalScrollTop` 设为下一段起点、`el.scrollTop=0`（isProgrammatic 屏蔽回弹）；向上滚用 wheel 跳上一段底部。以 globalScrollTop 为唯一真相、段由位置反查，避免段边界重建导致错位。
- 滚动锚定：测量导致视口上方的 item 高度变化时，`globalScrollTop += delta` 并 syncScrollPosition，避免内容跳动。
- 关键 prop：`estimatedItemHeight` 建议取 item 高度上界（高估安全、低估有超限风险）。
- 算法已 node 验证：前缀和/ findIndex(10万随机)/ 7 段连续覆盖且均 ≤13.5M 均正确。
- Bug 修复：`Cannot read properties of null (reading 'sum')` —— 原 `initHeights()` 只在 `onMounted` 里调用，而 `setup()` 渲染模板时 computed 已访问 `bit.sum`，此时 `bit` 仍为 null。改为在 setup 内同步调用 `initHeights()`（首次渲染前），并从 `onMounted` 移除该调用。
- Bug 修复（白屏）：滚动几下就白屏。根因有三：① 段相关 computed 只读 `globalScrollTop` 没读 `tick`，高度测量重建 `segmentsArr` 后它们用过期段、可能越界；② 跨段时 `segmentIndexAt(globalScrollTop)` 用旧段信息，会算出错误 `globalScrollTop`，使 `bit.sum(极大值)` 得 `NaN`，phantom 高度变 `NaN` 整片空白；③ `isProgrammatic`+60ms 定时器抑制在高频滚动下失效，造成递归横跳。
  - 重写模型：位置真源改为 `(displaySegIndex, containerScrollTop)`，二者推导 `globalTop`（仅用于渲染）；所有段相关 computed 都读 `tick` 防过期；跨段靠确定性重算（向下到底→`displaySegIndex++`+`scrollTop=0`，回顶后不会重复触发；向上到顶→`handleWheel` 跳上一段底部，仅此处用 `suppressNextScroll` 屏蔽一次程序化 scroll 事件）；分段重建时用全局锚点(视口顶像素)精确还原 `displaySegIndex`+`containerScrollTop`。
  - node 模拟 20000 步滚动+测量+重建：无 NaN/越界/崩溃，末项可达，每段 ≤ 上限。
- Bug 修复（item 滚动后消失）：`offsetY` 多减了一次 `localScrollTop`。`visible-area` 是容器内绝对定位元素、会随滚动一起上移，且 `startIndex` 已通过 `globalTop=segStartOffset+localScrollTop` 计入滚动量，故 `offsetY` 只需等于 `bit.sum(startIndex)-segStartOffset`（段内全局偏移），不能再减 `localScrollTop`，否则滚动量被减两遍、item 成倍飞出视口上方。对照可正常工作的 `SegmentedVirtualList.vue`（其 `offsetY=startIndex*itemHeight` 同样不减 scrollTop）确认。node 验证 41 个滚动位置渲染窗口均覆盖视口（PASS）。
- Demo 调整：`DynamicSegmentedDemo.vue` 高度随机区间改为 40~60（`40+((i*37)%21)`），`estimated-item-height` 相应改为上界 60。
