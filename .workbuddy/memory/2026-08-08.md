## 修复 apps/all-blue 无法 pnpm start:dev 启动的问题

**问题**：apps/all-blue（NestJS 项目）继承根 tsconfig.json 后，无法用 `pnpm start:dev` 启动，报 `Cannot find module '/Users/vwangyi/onepiece/dist/main'`。

**根因**：根 tsconfig.json 是为 Vue 前端设计的，包含多个不适用于 NestJS 的配置：

1. `noEmit: true` — 导致 tsc 不输出 .js 文件
2. `outDir: "./dist"` — 继承后解析为项目根的 dist/ 而非子包的 dist/
3. `module: "esnext"` / `moduleResolution: "bundler"` — NestJS 需要 commonjs / node
4. `include: ["apps/all-blue"]` — 导致输出保留 src/ 子目录层级
5. `resolvePackageJsonExports: true` / `noUncheckedSideEffectImports: true` — 仅在 node16/nodenext/bundler 模式下有效

**修复**：在 `apps/all-blue/tsconfig.json` 中覆盖了以上配置（noEmit、outDir、module、moduleResolution、target、types、lib、allowImportingTsExtensions、resolvePackageJsonExports、noUncheckedSideEffectImports、include），每项都加了中文注释说明原因。

**验证**：修复后 `nest build` 编译成功，`dist/main.js` 路径正确，`start:dev` 正常启动并监听 3000 端口。

## 修复 IDE 报 "找不到命名空间 Express" 的问题

**问题**：`upload.controller.ts` 中 `Express.Multer.File` 在 IDE 报错"找不到命名空间 Express"，但 tsc 编译无错误。

**根因**：pnpm monorepo 中 `@types` 包只安装在根 `node_modules/@types/`，子项目 `apps/all-blue/node_modules/@types/` 不存在。tsc 会自动向上查找父目录的 `node_modules/@types/`，但 IDE 的语言服务可能只看 tsconfig 当前目录，找不到 `@types/multer`（该包通过 `declare global { namespace Express { ... } }` 注入全局类型）。

**修复**：在 `apps/all-blue/tsconfig.json` 添加 `typeRoots: ["./node_modules/@types", "../../node_modules/@types"]`，显式告诉 IDE 去根目录找 @types 包。

## 修复 Express.Multer.File 找不到命名空间 Express（最终方案）

**问题**：上述 typeRoots 方案未解决，IDE 仍然报错。

**排查过程**：

1. 尝试 `.npmrc` 添加 `public-hoist-pattern[]=*types*` — 无效，子项目 node_modules 仍无 @types
2. 尝试在 `apps/all-blue/package.json` 添加 `@types/multer` 等 devDependencies — pnpm 正确链接了，但 tsc 仍报错
3. 通过 `tsc --showConfig` 发现根因：根 tsconfig.json 中 `"types": []` 被取消注释，导致不自动包含任何 @types 包

**真正根因**：根 tsconfig.json 第 16 行 `"types": []` — 注释写的是"表示包含所有的types"但实际含义是**排除所有 @types 包**。TypeScript 规则：不写 types 字段=包含全部；`types: []`=排除全部；`types: ["node"]`=只包含 node。

**最终修复**：

1. 在 `apps/all-blue/tsconfig.json` 添加 `"types": ["node", "jest", "multer"]` 覆盖根配置的空数组
2. 在 `apps/all-blue/package.json` devDependencies 添加 `@types/express`、`@types/jest`、`@types/multer`、`@types/node`、`@types/supertest`（pnpm 严格隔离要求子项目声明自己的 @types 依赖）
3. 撤销 `.npmrc` 中的 `public-hoist-pattern` 和 tsconfig 中的 `typeRoots`（均无效）
4. 根 tsconfig.json 中 `"types": []` 和 `"typeRoots"` 保持不变（Vue 前端用）

**验证**：tsc --noEmit 退出码 0，nest build 编译通过，NestJS 应用正常启动。
