## 执行上下文
1. 执行上下文是V8引擎执行代码前创建的环境对象，主要记录了this指向、词法环境、变量环境。

词法环境保存了 let/const变量和函数 以及outer。 outer指向父级的词法环境，也就是作用域链。 
- 函数调用前，会创建函数执行上下文并压入执行栈中，var初始化为undefined 函数初始化为函数对象 是一个引用地址指向堆内存中的实际对象。 let/const没有初始化进入暂时性死区，赋值前访问将报错。
- 函数执行时，逐行执行代码，给变量更新值。 逐行执行代码，对变量赋值，并执行函数逻辑。
- 函数执行结束后，对应的执行上下文从调用栈中弹出。、


词法环境是 this outer letconst变量 函数

变量环境也是一种词法环境，只是里面专门用来记录var变量 （var和let cosnt的区别需要我说一下吗）
## 执行上下文栈
1. 执行上下文栈 是 V8引擎 采用先进后出的栈结构 来管理 执行上下文。


当v8执行js代码前，会先创建一个全局执行上下文，并压入执行栈，js是单线程语言，所以有且仅有一个执行栈。

当执行函数前会创建一个函数执行上下文，压入执行栈。
函数执行过程中会更新执行上下文里面记录的值。
函数执行完毕后 对应的执行上下文就会出栈并销毁。

如果递归没有结束条件，就会导致执行栈的栈溢出。

当执行栈空闲时，事件循环会从任务队列中取出新的任务继续执行。

- 遇到异步任务不会立即进入执行栈，而是等待达到触发条件后进入事件循环的任务队列进行排队，
事件循环会在 执行栈为栈空时，按照排队规则依次取出任务进入执行栈。
tips: 变量对象 活跃对象 是es5的说法 这里不研究。

## 栈空指什么
栈空指的是 只有全局上下文，没有其他上下文 

你可能已经注意到了，在创建阶段let和const变量为uninitialized，而var变量为undefined。这是因为在创建阶段时，引擎检查代码找出变量和函数声明，虽然函数声明完全存储在环境中，但是变量最初设置为undefined（var情况下），或者未初始化（let和const情况下）。这就是为什么你可以在声明之前访问 var 定义的变量（虽然是undefined），但是在声明之前访问let和const的变量会得到一个引用错误。这就是我们说的变量声明提升。















## 
执行栈为空 不是说全局执行上下文没有了 而是说 只剩全局上下文 没有其他函数执行上下文就是栈空了

事件循环会循环检查执行栈是否为空，如果为空就从任务队列中取出任务放入执行栈中


浏览器的 JavaScript 运行在渲染主线程中，渲染主线程既负责页面渲染，也负责执行 JS。 是互斥的
执行 JS 时会创建执行上下文并压入执行栈。由于 JS 是单线程的，异步任务无法立即执行，只能先交给浏览器其他线程处理，完成后进入任务队列。事件循环机制会不断检查执行栈是否为空，空了以后先执行一个宏任务，再清空所有微任务，然后进行页面渲染，之后进入下一轮循环。




执行代码时 同步任务会立即执行 产生的异步任务会遵循事件循环机制的排队规则 在异步队列里面排队。
当事件循环检查到 执行栈栈空时 会将异步队列的任务放到执行栈中由主线程执行。
