# 设计模式 

- 设计模式是在特定场景下用固定套路解决问题的方案
- 模式是解决某一类问题的方法论


- 设计模式是 面向对象语言日积月累

不遵守语法导致bug就是违背法律
不遵守设计模式就是违背道德原则

- 设计模式六大原则
1. 高内聚 低耦合  复用性  维护性

耦合度是什么：耦合是指某两个事物之间如果存在一种相互作用、相互影响的关系，
复杂度是什么：复杂度高。 代码质量不高 可维护性差 复用性差 扩展性差 （所有功能都写道一个函数里面 复杂度就高）




开发流程：
1. 优先降低复杂度，尽量降低耦合度
2. 利用单一职责原则，开闭原则，里氏替换原则。 增加耦合度 降低复杂度。
3. 迪米特法则 减少耦合度
3. 依赖倒置原则 消除可以没有的耦合



面向对象设计 SOLID 五大原则之一
- 单一职责原则：一个函数只做一件事
- 开闭原则：封装模块应该 对扩展开放，对修改关闭。
- 里氏替换原则：子类可以扩展父类的功能，但不能改变父类原有的功能。
- 迪米特法则：最小知道原则 封装模块传入参数越少越好，最好是不传参数。
- 接口分离原则：不要一个接口实现所有增删改查
- 依赖倒置原则：原本两个模块直接依赖会导致耦合度增加。可以增加一层变为间接依赖从而降低耦合，比如vue的pinia，依赖数据状态而不是彼此依赖。 
  
代码质量是高度是素质高低。学会权衡才是高价值的开发经验。


优化屎山代码 
1. 用 单一职责原则 开闭原则 里氏替换原则 分成很多模块降低复杂度。 
2. 最后用依赖倒置原则 消除没必要的耦合
3. 虽然 业务压力 优先于 代码质量，但并不意味着屎山是理所当然，业务压力和代码质量应该权衡取舍，
4. 在大的架构模块上应该注重代码质量素质，在局部模块可临时放弃质量，局部模块虽然可能屎山 但这是可控的。
5. 作为管理着 应该负责大架构模块保证涉及全局的应该重视质量，而分出去的局部模块，则可以敏捷开发，不会涉及全局。



高内聚低耦合 
（在一些不懂的人眼里 只看时间不看质量 没必要上设计模式 怎么快怎么来 因为一些sb压根不懂）


先原则，再模式。原则是理论，模式是实践。做任何事情都有时间成本的。




## 单例模式

- 定义：整个应用只有一个实例。比如 vuex/pinia。 应用场景是创建对象时。不管创建多少次都是同一个对象。

比如 一个登录弹窗对象，没有必要每次点开弹窗都创建一个新的。


## 代理模式
- 给一个对象 提供的 代理对象，通过这个代理对象 来访问原对象。 类似中介，代理对象可能删除或增加一些功能。
