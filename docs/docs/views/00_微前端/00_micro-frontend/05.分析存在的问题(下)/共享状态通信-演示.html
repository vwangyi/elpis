共享状态通道

手写一个最小 initGlobalState，到底在干什么

主应用先创建一份共享状态，订单子应用和财务子应用在 mount 时调用 onGlobalStateChange 订阅，在 unmount 时调用 offGlobalStateChange 退订。谁调用 setGlobalState 改了 tenant、theme、unreadCount，所有还在运行的子应用都会立刻收到更新。

这套手写共享状态，到底在干嘛

它的目标不是取代业务通信，而是把“多个子应用共享同一份状态”的通道先收成一套固定动作。

好处

  • 主应用和子应用都围着同一份状态对象说话，状态来源更统一。
  • 每个子应用只需要会订阅、写 patch、退订，不必为 tenant、theme、unread 各写一套专用回调。
  • 后面看到 initGlobalState、onGlobalStateChange、setGlobalState、offGlobalStateChange 时，学生一眼就能对上动作含义。

坏处

  • 如果什么都往共享状态里塞，它就会变成一个没有边界的大垃圾桶。
  • 谁都能 set 时，要额外约定哪些字段允许谁改，不然状态源头会变得混乱。
  • 订阅、退订、字段约束、日志追踪都还得自己维护，继续手写就会慢慢逼近一个小框架。
