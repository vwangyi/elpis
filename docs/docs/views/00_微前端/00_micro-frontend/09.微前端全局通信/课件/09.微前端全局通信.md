# 09. 微前端全局通信

## 这节课要拿到什么结果

这一课只解决一个问题：主应用、订单子应用、财务子应用拆开以后，怎么共享一份系统级状态。

本节示例用的是“待处理事项数”：

- 主应用侧边栏显示当前待处理事项数
- 订单子应用处理一条订单，待处理事项数减 1
- 财务子应用新增一条财务待办，待处理事项数加 1
- 三个应用看到的是同一个当前值

先记住一句话：

```txt
代码拆开了，但用户看到的还是一个系统。
```

所以有些状态不能只放在某个子应用里。比如登录用户、消息数、待办数、主题、语言、全局权限。

但不要把所有东西都塞进全局状态。

```txt
多个应用都需要知道，并且它代表整个系统，才考虑全局通信。
只属于某个页面或某个子应用的状态，就留在它自己内部。
```

---

## 1. 微前端里常见的通信方案

### 1.1 props 传参

解释：主应用挂载子应用时，把数据和方法传进去。

它最像“主应用把一包东西交给子应用”。这包东西可以是普通数据，也可以是函数。

最小写法：

```js
registerMicroApps([
  {
    name: "order-app",
    entry: "//localhost:5174",
    container: "#subapp-viewport",
    activeRule: "/orders",
    props: {
      defaultPath: "/orders/list",
      navigate: (path) => router.push(path),
    },
  },
]);
```

子应用在 `mount(props)` 里接收：

```js
export async function mount(props = {}) {
  console.log(props.defaultPath);
  props.navigate?.("/orders/detail/2048");
}
```

适合：

- 主应用给子应用传启动参数
- 主应用给子应用传一个回调方法
- 子应用向主应用申请做某件事，比如“请主应用帮我改 URL”

前面路由治理里已经用过：

```js
props: {
  defaultPath: microApp.defaultPath,
  navigate: (path) => router.push(path),
}
```

props 很重要，因为主应用和子应用之间跨过的第一道边界，经常就是 props。

但 props 也有边界：

```txt
props 更适合“交付能力”或“传递初始信息”。
如果多个应用都要长期订阅同一份状态，只靠 props 会越来越散。
```

### 1.2 自定义事件

解释：一个应用通过 `window.dispatchEvent` 发事件，另一个应用通过 `window.addEventListener` 监听。

它最像“广播一声，谁监听了谁就处理”。

最小写法：

```js
window.dispatchEvent(
  new CustomEvent("order:finished", {
    detail: {
      orderId: "O-2048",
    },
  }),
);
```

另一个应用监听：

```js
function handleOrderFinished(event) {
  console.log("订单处理完成", event.detail.orderId);
}

window.addEventListener("order:finished", handleOrderFinished);
window.removeEventListener("order:finished", handleOrderFinished);
```

适合：

- 轻量通知
- 临时联动
- “刚刚发生了一件事”的场景

但它不适合表达“当前还剩几条待办”。

原因是：事件只代表发生过一次动作。财务子应用如果晚一点才加载，它听不到之前已经发生过的事件，也就不知道当前值是多少。

所以本节的 `pendingCount` 不能只靠自定义事件。

本节项目里也加了一个所见即所得的按钮。

文件位置：`10/01/order-app/src/App.vue`

修改方式：`局部修改`

订单子应用点击“发送操作提醒”时，发出一个自定义事件：

```js
function sendOrderNotice() {
  window.dispatchEvent(
    new CustomEvent("order:notice", {
      detail: {
        message: "订单系统刚刚发出一条操作提醒",
        orderId: "O-2048",
      },
    }),
  );
}
```

文件位置：`10/01/main-app/src/App.vue`

修改方式：`局部修改`

主应用负责监听这个事件：

```js
const latestOrderNotice = ref("暂无订单提醒");

function handleOrderNotice(event) {
  const { message, orderId } = event.detail || {};
  latestOrderNotice.value = orderId ? `${message}：${orderId}` : message;
}

onMounted(() => {
  window.addEventListener("order:notice", handleOrderNotice);
});

onBeforeUnmount(() => {
  window.removeEventListener("order:notice", handleOrderNotice);
});
```

这个例子只表示“刚刚发生了一次提醒”。它没有保存一份所有应用都能随时读取的当前状态，所以它和后面的全局状态不是一回事。

### 1.3 全局状态

解释：维护一份共享状态，关心它的应用订阅变化，需要改它的应用按约定提交修改。

它最像“大家都看同一块状态面板”。

适合：

- 当前登录用户
- 待办数、消息数
- 全局主题
- 语言
- 少量系统级配置

本节重点就是全局状态。

但它也不是万能方案。订单列表、财务明细、复杂表单草稿，不应该全部放进全局状态。全局状态越大，应用之间越容易互相牵制。

这里顺便回答一个容易疑惑的问题：

> qiankun 的全局状态不还是通过 props 给子应用的吗？那为什么 props 和全局状态要分开讲？

因为它们不是同一层概念。

```txt
props 是“东西怎么跨过主应用和子应用边界”。
全局状态是“跨过去以后，大家按什么模型共享和更新状态”。
```

也可以简单记成：

```txt
props 更像递送通道。
全局状态更像通信模型。
```

qiankun 确实会把 `onGlobalStateChange`、`setGlobalState`、`offGlobalStateChange` 这些能力放进子应用生命周期的 props 里。

但子应用拿到的不是一个普通值，而是一套“订阅、修改、取消订阅”的状态协作能力。

### 1.4 postMessage

解释：窗口和窗口之间发消息。

它最常见的场景是 iframe。

比如主应用里嵌了一个 iframe 老系统，主应用想告诉 iframe 当前用户信息：

```js
const iframeWindow = document.querySelector("iframe").contentWindow;

iframeWindow.postMessage(
  {
    type: "user:update",
    payload: {
      name: "张三",
    },
  },
  "http://localhost:5174",
);
```

iframe 页面里接收：

```js
window.addEventListener("message", (event) => {
  if (event.origin !== "http://localhost:5173") return;

  if (event.data.type === "user:update") {
    console.log(event.data.payload.name);
  }
});
```

适合：

- iframe 通信
- 跨窗口通信
- 跨域页面通信

注意：`postMessage` 一定要校验 `origin`，否则会有安全风险。

### 1.5 URL

解释：把状态放进地址里。

它不是很多人第一时间想到的“通信方案”，但它非常重要。

URL 表达的是：

```txt
当前在哪个页面？
当前看的是哪个详情？
当前筛选条件是什么？
```

比如：

```txt
/orders/detail/2048
/finance/refund/1024
/orders/list?status=pending&page=2
```

适合：

- 当前页面
- 详情 ID
- tab
- 搜索条件
- 分页
- 可分享、可恢复的筛选条件

如果一个状态需要刷新恢复，优先想 URL，不要先塞进全局状态。

一句话总结：

```txt
URL 解决“当前在哪、能不能恢复”。
props 解决“主应用怎么把能力交给子应用”。
自定义事件解决“一次动作通知”。
全局状态解决“多个应用共享当前值”。
postMessage 解决“iframe、跨窗口、跨域页面怎么说话”。
```

## 2. qiankun 全局状态是什么

先不用 qiankun，自己写一个最小版也能看懂：

```js
const state = {
  pendingCount: 3,
};

const listeners = new Set();

function subscribe(listener) {
  listeners.add(listener);
  listener(state);
  return () => listeners.delete(listener);
}

function setState(partialState) {
  Object.assign(state, partialState);
  listeners.forEach((listener) => listener(state));
}
```

这套模型有 4 个动作：

```txt
保存一份共享状态
订阅状态变化
提交状态修改
取消订阅
```

qiankun 提供的就是这套思想在微前端里的实现。

主应用调用：

```js
initGlobalState(initialState);
```

子应用通过生命周期 `props` 拿到：

```js
props.onGlobalStateChange;
props.setGlobalState;
props.offGlobalStateChange;
```

链路是：

```txt
主应用 initGlobalState
  -> qiankun 保存全局状态
  -> 子应用 mount(props) 收到全局状态方法
  -> 子应用订阅状态变化
  -> 主应用或子应用 setGlobalState
  -> 所有订阅者收到新状态
```

## 3. 两个必须记住的限制

### 3.1 只能改初始化时声明过的一层字段

主应用初始化时写了：

```js
const initialState = {
  pendingCount: 3,
  lastUpdatedBy: "main-app",
};
```

后面可以改：

```js
setGlobalState({
  pendingCount: 2,
  lastUpdatedBy: "order-app",
});
```

但不要突然加一个没声明过的字段：

```js
setGlobalState({
  unknownField: "xxx",
});
```

qiankun 会忽略这个字段，并在控制台提示类似：

```txt
[qiankun] 'unknownField' not declared when init state！
```

原因很简单：全局状态是跨应用契约，不是随手扩展的普通对象。

如果真的要新增系统级字段，应该先回到主应用初始化状态里声明：

```js
const initialState = {
  pendingCount: 3,
  lastUpdatedBy: "main-app",
  unreadMessageCount: 0,
};
```

### 3.2 同一个应用同一时间只保留一个监听

不要在同一个子应用里到处写：

```js
props.onGlobalStateChange((state) => {
  console.log("第一个监听", state.pendingCount);
});

props.onGlobalStateChange((state) => {
  console.log("第二个监听", state.pendingCount);
});
```

第二次调用会覆盖第一次。

更稳的做法是：

```txt
子应用入口处订阅一次
  -> 放进子应用自己的 store、Context、响应式对象
  -> 页面组件从本应用内部状态读取
```

qiankun 负责应用之间通信。子应用内部状态分发，交给子应用自己的框架。

## 4. 修改主应用：初始化全局状态

文件位置：`10/01/main-app/src/global-state.js`

修改方式：`新增文件`

```js
import { initGlobalState } from "qiankun";
import { reactive } from "vue";

const initialState = {
  pendingCount: 3,
  lastUpdatedBy: "main-app",
};

export const hostGlobalState = reactive({ ...initialState });

export const globalActions = initGlobalState(initialState);

globalActions.onGlobalStateChange((state) => {
  hostGlobalState.pendingCount = state.pendingCount;
  hostGlobalState.lastUpdatedBy = state.lastUpdatedBy;
}, true);

export function updatePendingCount(nextCount, lastUpdatedBy = "main-app") {
  globalActions.setGlobalState({
    pendingCount: Math.max(0, nextCount),
    lastUpdatedBy,
  });
}
```

看懂 4 点：

- `initialState` 声明全局状态字段边界
- `initGlobalState(initialState)` 创建 qiankun 全局状态
- 主应用自己也订阅这份状态，并同步到 Vue 的 `reactive` 对象里展示
- `fireImmediately = true` 表示订阅后立刻执行一次回调，页面初始渲染就能拿到当前值

## 6. 修改订单子应用：Vue 里接住全局状态

订单子应用是 Vue，并且上一节已经用 `loadMicroApp` 做了保活。

所以这里要注意：

```txt
切到财务时，订单子应用只是隐藏，不卸载。
监听不应该在隐藏时清掉。
真正 unmount 时再 offGlobalStateChange。
```

### 6.1 订单入口绑定 qiankun 全局状态

文件位置：`10/01/order-app/src/main.js`

修改方式：`局部修改`

准备一份 Vue 响应式状态：

```js
const sharedGlobalState = reactive({
  pendingCount: 0,
  lastUpdatedBy: "独立运行",
});
```

保存 qiankun 注入的方法：

```js
let setGlobalState = null;
let offGlobalStateChange = null;
```

同步状态：

```js
function syncSharedGlobalState(state = {}) {
  if (typeof state.pendingCount === "number") {
    sharedGlobalState.pendingCount = state.pendingCount;
  }

  if (state.lastUpdatedBy) {
    sharedGlobalState.lastUpdatedBy = state.lastUpdatedBy;
  }
}
```

绑定 qiankun props：

```js
function bindGlobalState(props = {}) {
  setGlobalState = props.setGlobalState || null;
  offGlobalStateChange = props.offGlobalStateChange || null;

  props.onGlobalStateChange?.((state) => {
    syncSharedGlobalState(state);
  }, true);
}
```

修改待办数：

```js
function changePendingCount(delta) {
  const nextCount = Math.max(0, sharedGlobalState.pendingCount + delta);

  if (setGlobalState) {
    setGlobalState({
      pendingCount: nextCount,
      lastUpdatedBy: "order-app",
    });
    return;
  }

  syncSharedGlobalState({
    pendingCount: nextCount,
    lastUpdatedBy: "order-app",
  });
}
```

兜底分支是给独立运行用的。独立运行时没有主应用，也没有 qiankun 注入的 `setGlobalState`。

把状态提供给页面：

```js
app.provide("sharedGlobalState", {
  state: sharedGlobalState,
  changePendingCount,
});
```

生命周期里调用：

```js
export async function mount(props = {}) {
  bindGlobalState(props);
  await render(props);
}

export async function unmount() {
  offGlobalStateChange?.();
  app?.unmount();
}
```

## 7. 修改财务子应用：React 里用小 store 接住全局状态

财务子应用是 React。不要在每个页面组件里直接写 `props.onGlobalStateChange`。

本节做法是：入口绑定 qiankun，全局状态文件维护一个外部 store，页面通过 hook 读取。

### 7.1 新建财务全局状态桥接文件

文件位置：`10/01/finance-app/src/global-state.jsx`

修改方式：`新增文件`

```jsx
import { useSyncExternalStore } from "react";

let snapshot = {
  pendingCount: 0,
  lastUpdatedBy: "独立运行",
};

let setGlobalState = null;
let offGlobalStateChange = null;

const listeners = new Set();
```

`snapshot` 是财务子应用自己保存的当前状态。它只是普通 JS 变量，不是 React state。

所以变更后要通知 React：

```jsx
function emitChange() {
  listeners.forEach((listener) => listener());
}

function syncSnapshot(state = {}) {
  snapshot = {
    ...snapshot,
    ...(typeof state.pendingCount === "number"
      ? { pendingCount: state.pendingCount }
      : null),
    ...(state.lastUpdatedBy ? { lastUpdatedBy: state.lastUpdatedBy } : null),
  };
  emitChange();
}
```

这里要创建新对象，不要原地改 `snapshot`。React 更容易根据新引用判断外部快照变了。

绑定 qiankun props：

```jsx
export function bindGlobalState(props = {}) {
  setGlobalState = props.setGlobalState || null;
  offGlobalStateChange = props.offGlobalStateChange || null;

  props.onGlobalStateChange?.((state) => {
    syncSnapshot(state);
  }, true);
}
```

卸载时清理：

```jsx
export function unbindGlobalState() {
  offGlobalStateChange?.();
  setGlobalState = null;
  offGlobalStateChange = null;
}
```

修改待办数：

```jsx
export function changePendingCount(delta) {
  const nextCount = Math.max(0, snapshot.pendingCount + delta);

  if (setGlobalState) {
    setGlobalState({
      pendingCount: nextCount,
      lastUpdatedBy: "finance-app",
    });
    return;
  }

  syncSnapshot({
    pendingCount: nextCount,
    lastUpdatedBy: "finance-app",
  });
}
```

给 React 组件用的 hook：

```jsx
export function useSharedGlobalState() {
  return useSyncExternalStore(
    (listener) => {
      listeners.add(listener);
      return () => listeners.delete(listener);
    },
    () => snapshot,
    () => snapshot,
  );
}
```

`useSyncExternalStore` 的白话意思：React 组件要读取一个外部 store 时，用它来订阅变化、同步拿最新快照。

链路是：

```txt
qiankun 状态变化
  -> syncSnapshot 更新 snapshot
  -> emitChange 调用 React 给的 listener
  -> React 重新渲染组件
  -> 组件通过 () => snapshot 拿最新值
```
