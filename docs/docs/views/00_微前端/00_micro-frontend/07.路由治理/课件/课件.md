# 07. 路由处理

## 这节课要拿到什么结果

这一课只看一件事：微前端里，路由到底该谁管。

你要记住 4 句话：

- 浏览器地址栏只有一个，`window.history` 也只有一份
- 多个应用都直接改 `window.history`，就可能互相覆盖路由状态
- `memory router` 可以隔离冲突，但单独使用会牺牲地址栏同步
- 企业项目要先决定“谁拥有地址栏”，再决定子应用怎么同步页面

配套代码看 3 份，实际外层目录按你的项目摆放为准：

- `01`：先用 `memory router` 止住冲突
- `02`：`memory router + 主应用统一导航`
- `03`：`History + Base/Basename` 方案

---

## 1. 路由冲突到底是什么

先说白话：

主应用、订单子应用、财务子应用虽然是 3 个项目，但嵌到同一个页面后，它们用的是同一个浏览器地址栏。

再说术语：

它们共享同一个 `window.history`。如果多个路由库都往 `history.state` 里写自己的数据，就可能互相覆盖。

当前项目里有 3 套路由：

- 主应用：Vue Router，history 模式
- 订单子应用：Vue Router，独立运行时 hash 模式
- 财务子应用：React Router，独立运行时 browser history 模式

注意：hash router 也不等于完全不碰 `window.history`。它只是把业务路径放到 `#` 后面，但初始化、跳转时仍然可能调用浏览器 History API。

所以不要简单记成“hash 一定安全，history 一定危险”。这节课真正要判断的是：

```txt
谁负责写浏览器地址栏？
谁负责维护 window.history.state？
```

## 2. 先复现问题

进入第一个项目目录，也就是 `01`：

```bash
cd 01
pnpm install
```

启动 3 个项目：

```bash
pnpm dev:main
pnpm dev:order
pnpm dev:finance
```

默认端口：

- 主应用：`http://localhost:5173`
- 订单子应用：`http://localhost:5174`
- 财务子应用：`http://localhost:5175`

操作顺序：

1. 打开主应用
2. 进入订单子应用
3. 在订单子应用里切到详情页
4. 切到财务子应用
5. 在财务子应用里切到开票页或退款页
6. 再点击主应用菜单里的订单子应用

可能会看到类似错误：

```txt
Failed to execute 'replaceState' on 'History':
A history state object with URL 'http://localhost:5173undefined/' cannot be created
```

白话解释：路由库想更新浏览器历史记录，但拼出来的地址里出现了 `undefined`，浏览器拒绝了这次操作。

原因是：Vue Router 和 React Router 写入的 `history.state` 结构不一样。

Vue Router 大概需要这些字段：

```js
{
  back: null,
  current: "/orders/list",
  forward: null,
  position: 4,
  replaced: true,
  scroll: null
}
```

React Router 大概会写这些字段：

```js
{
  usr: null,
  key: "xxx",
  idx: 1
}
```

它们各自在独立项目里都没错。问题出在嵌入后，它们写的是同一份 `window.history.state`。

一句话总结：

```txt
qiankun 能根据 URL 激活子应用，但不会自动统一不同路由库的 history.state。
```

## 3. 方案一的第一步：Memory Router 止血

### 3.1 思想

先让子应用嵌入主应用时不要直接写浏览器地址栏。

子应用内部页面仍然可以切换，但路由状态存在内存里，不写 `window.history`。

术语上，这就是 `memory router`。

它解决的是：

```txt
子应用内部跳转，不再覆盖主应用的 history.state。
```

### 3.2 订单子应用

文件位置：`01/order-app/src/main.js`

修改方式：`局部修改`

核心代码：

```js
const history = window.__POWERED_BY_QIANKUN__
  ? createMemoryHistory()
  : createWebHashHistory();

router = createOrderRouter(history);

if (window.__POWERED_BY_QIANKUN__) {
  router.push(window.location.pathname || "/orders/list");
}
```

看懂这 3 点就够了：

- 嵌入主应用时，用 `createMemoryHistory()`
- 独立运行时，继续用原来的 hash 路由
- memory router 不读地址栏，所以要手动 `router.push()` 到当前路径

### 3.3 财务子应用

文件位置：`01/finance-app/src/router.jsx`

修改方式：`局部修改`

核心代码：

```js
export function createFinanceRouter(options = {}) {
  const { memory = false, initialPath = defaultFinancePath } = options;

  if (memory) {
    return createMemoryRouter(routes, {
      initialEntries: [initialPath],
    });
  }

  return createBrowserRouter(routes);
}
```

文件位置：`01/finance-app/src/main.jsx`

修改方式：`局部修改`

挂载时传入参数：

```js
router = createFinanceRouter(
  qiankunWindow.__POWERED_BY_QIANKUN__
    ? {
        memory: true,
        initialPath: window.location.pathname || "/finance/bills",
      }
    : undefined,
);
```

这里用 `qiankunWindow.__POWERED_BY_QIANKUN__`，是因为财务子应用是 Vite 项目，通过 `vite-plugin-qiankun` 接入 qiankun。

### 3.4 这一步的结果

再按原来的流程操作：

```txt
订单子应用 -> 订单详情 -> 财务子应用 -> 开票处理 -> 订单子应用
```

预期结果：

- 不再出现 `localhost:5173undefined/`
- 子应用内部页面可以切换
- 但地址栏不一定跟着子应用内部页面变化

所以这一步只是止血。

`memory router` 隔离了冲突，但如果不做 URL 同步，会影响：

- 刷新恢复
- 复制链接
- 浏览器前进后退
- 菜单高亮、权限、埋点、面包屑

## 4. 方案一完整版：Memory Router + 主应用统一导航

### 4.1 思想

子应用不直接改地址栏。

子应用只告诉主应用：

```txt
我要去 /finance/invoice/908
```

真正执行 `router.push()` 的是主应用。

流程：

1. 主应用注册子应用时传入导航方法
2. 子应用嵌入态使用 memory router
3. 子应用内部点击页面时调用主应用传来的 `navigate(path)`
4. 主应用执行 `router.push(path)`
5. 地址栏变化
6. 子应用 memory router 渲染对应页面

### 4.2 主应用传导航能力

文件位置：`02/main-app/src/micro-apps.js`

修改方式：`局部修改`

```js
function createRouteProps(router, microApp) {
  return {
    defaultPath: microApp.defaultPath,
    getCurrentPath: () => window.location.pathname,
    navigate: (path) => {
      const targetPath = path || microApp.defaultPath;
      if (router.currentRoute.value.path !== targetPath) {
        void router.push(targetPath);
      }
    },
  };
}
```

这 3 个字段的作用：

- `defaultPath`：默认进入哪个页面
- `getCurrentPath()`：子应用挂载时拿当前地址
- `navigate(path)`：子应用申请跳转，主应用真正改地址栏

注册子应用时传入：

```js
props: createRouteProps(router, microApps.order);
```

### 4.3 主应用启动 qiankun

文件位置：`02/main-app/src/main.js`

修改方式：`局部修改`

```js
router.isReady().then(async () => {
  app.mount("#app");
  await nextTick();
  setupQiankun(router);
});
```

顺序不能乱：先挂主应用，等子应用容器渲染出来，再启动 qiankun。

### 4.4 子应用使用主应用导航能力

文件位置：`02/order-app/src/main.js`

修改方式：`局部修改`

```js
const isEmbedded = window.__POWERED_BY_QIANKUN__;
const initialPath = props.getCurrentPath?.() || props.defaultPath;

router = createOrderRouter(
  isEmbedded ? createMemoryHistory() : createWebHashHistory(),
);

app.provide("hostNavigation", {
  isEmbedded,
  navigate: props.navigate,
});

if (isEmbedded) {
  await router.push(initialPath);
}
```

文件位置：`02/finance-app/src/main.jsx`

修改方式：`局部修改`

```jsx
const isEmbedded = qiankunWindow.__POWERED_BY_QIANKUN__;

router = createFinanceRouter(
  isEmbedded
    ? {
        memory: true,
        initialPath: props.getCurrentPath?.() || props.defaultPath,
      }
    : undefined,
);

root.render(
  <HostNavigationContext.Provider
    value={{ isEmbedded, navigate: props.navigate }}
  >
    <RouterProvider router={router} future={routerFuture} />
  </HostNavigationContext.Provider>,
);
```

这里要记住边界：

```txt
子应用只依赖 navigate 这个协议，不直接依赖主应用内部的 Vue Router 实例。
```

### 4.5 适合场景

这套方案适合：

- Vue、React 等多技术栈混用
- 老项目接入
- 主应用要统一做权限、菜单、面包屑、页签、埋点
- 不希望子应用直接写浏览器 history

一句话：

```txt
主应用管 URL，子应用申请跳转。
```

## 5. 方案二：History + Base/Basename

### 5.1 思想

每个子应用分一个固定地址前缀。

```txt
/orders/*   订单子应用
/users/*    用户子应用
/finance/*  财务子应用
```

主应用看到 `/orders`，就挂订单子应用。订单子应用自己只关心 `/orders` 后面的内部页面。

Vue Router 里这个前缀叫 `base`，React Router 里叫 `basename`。

### 5.2 主应用定义一级路径

文件位置：`03/main-app/src/micro-apps.js`

修改方式：`局部修改`

```js
const microApps = {
  order: {
    name: "order-app",
    entry: "//localhost:5174",
    activeRule: "/orders",
    defaultPath: "/orders/list",
  },
  user: {
    name: "user-app",
    entry: "//localhost:5176",
    activeRule: "/users",
    defaultPath: "/users/list",
  },
  finance: {
    name: "finance-app",
    entry: "//localhost:5175",
    activeRule: "/finance",
    defaultPath: "/finance/bills",
  },
};
```

### 5.3 主应用路由保留容器

文件位置：`03/main-app/src/router/index.js`

修改方式：`局部修改`

```js
const routes = [
  { path: "/", redirect: "/orders/list" },
  { path: "/orders/:pathMatch(.*)*", component: RoutePortal },
  { path: "/users/:pathMatch(.*)*", component: RoutePortal },
  { path: "/finance/:pathMatch(.*)*", component: RoutePortal },
];
```

`RoutePortal` 只是子应用挂载容器，不是具体业务页面。

### 5.4 Vue 子应用配置 base

文件位置：`03/order-app/src/main.js`

修改方式：`局部修改`

```js
const history = window.__POWERED_BY_QIANKUN__
  ? createWebHistory("/orders")
  : createWebHashHistory();
```

这样订单子应用内部路由可以写：

```txt
/list
/detail/2048
/refund/1024
```

最终浏览器地址会是：

```txt
/orders/list
/orders/detail/2048
/orders/refund/1024
```

### 5.5 React 子应用配置 basename

文件位置：`03/finance-app/src/router.jsx`

修改方式：`局部修改`

```js
export function createFinanceRouter() {
  return createBrowserRouter(routes, {
    basename: qiankunWindow.__POWERED_BY_QIANKUN__ ? "/finance" : "/",
    // window: createStatePreservingWindow(),
  });
}
```

财务子应用内部路由写：

```txt
/bills
/invoice/908
/refund/1024
```

最终浏览器地址会是：

```txt
/finance/bills
/finance/invoice/908
/finance/refund/1024
```

### 5.6 这套方案的优点

优点：

- 子应用内部切路由时，地址栏天然变化
- 刷新能回到对应子页面
- 复制链接能直接打开对应页面
- 菜单、权限、埋点更容易围绕 URL 做

适合：

- 新项目
- URL 规划统一
- 路由生态一致，或者团队有统一路由封装

一句话：

```txt
每个子应用分一个 URL 命名空间，在自己的命名空间里自治。
```

## 6. History + Base/Basename 的注意点

`base` 和 `basename` 解决的是 URL 前缀问题，不自动解决 `history.state` 结构问题。

### 6.1 Vue 子应用内部路径和主应用完整路径不同

订单子应用配置了：

```js
createWebHistory("/orders");
```

浏览器地址是：

```txt
/orders/detail/2048
```

但订单子应用内部更关心：

```txt
/detail/2048
```

所以要区分：

```txt
地址栏路径：/orders/detail/2048
子应用内部路径：/detail/2048
主应用识别路径：/orders/detail/2048
```

当前 `03/main-app/src/App.vue` 里用 `normalizeCurrentHistoryStateForHost()` 做兜底：

```txt
在离开当前子应用之前，把当前历史记录整理成主应用能看懂的完整路径。
```

### 6.2 React Router 还要处理 state 兼容

React Router 的 `basename` 只说明财务子应用挂在 `/finance` 下面。

它不会自动保留 Vue Router 需要的 `back/current/forward/position` 等字段。

所以 `03/finance-app/src/router.jsx` 里准备了 `createStatePreservingWindow()`。

它的作用：

```txt
给 React Router 一个代理 window，拦截 pushState/replaceState。
React Router 写 state 时，先保留已有字段，再合并自己的字段。
```

课堂演示时可以先保持注释，复现问题：

```js
// window: createStatePreservingWindow(),
```

讲完原因后再打开：

```js
window: createStatePreservingWindow(),
```

再执行：

```txt
订单子应用 -> 订单详情 -> 财务子应用 -> 开票处理 -> 订单子应用
```

预期结果：

```txt
不再出现 localhost:5173undefined/ 报错。
```

## 7. 怎么选择方案

先问 4 个问题：

- 谁负责改地址栏？
- 谁负责保存当前路径？
- 谁负责刷新后恢复页面？
- 谁负责权限、菜单、埋点、页签？

### 7.1 选 Memory Router + 主应用统一导航

适合：

- 多技术栈混用
- 老系统接入
- 主应用要统一管权限、菜单、页签、埋点
- 不希望子应用直接写浏览器 history

结论：

```txt
主应用拥有地址栏，子应用通过协议申请跳转。
```

### 7.2 选 History + Base/Basename

适合：

- 新项目
- URL 规范能从一开始统一
- 路由库一致，或者有统一路由封装
- 希望子应用内部跳转天然反映到地址栏

结论：

```txt
每个子应用拥有自己的 URL 命名空间。
```

### 7.3 Hash 隔离

例子：

```txt
/finance/#/refund/1024
```

适合老项目迁移，成本低，服务端刷新压力小。

缺点是 URL 不够清爽，菜单、权限、埋点解析更麻烦。新项目一般不优先选。

## 8. 本节小结

微前端路由处理，不是背几个路由 API，而是先判断 ownership。

本节只要记住这些：

- 浏览器地址栏只有一个，`window.history` 也只有一份
- 多个路由库同时写 `history.state`，就可能互相覆盖
- `memory router` 负责隔离冲突
- `memory router + 主应用统一导航` 适合多技术栈和主应用强管控场景
- `History + Base/Basename` 适合新项目和统一 URL 规划场景
- `base/basename` 只解决 URL 命名空间，不自动解决 `history.state` 结构差异

最后一句：

```txt
先决定谁拥有地址栏，再决定子应用怎么同步内部页面。
```
