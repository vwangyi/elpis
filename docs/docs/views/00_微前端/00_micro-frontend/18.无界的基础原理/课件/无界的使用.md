# 18. 无界的使用

## 1. 无界的运行结构

无界将子应用的运行环境和显示环境分开：

```txt
iframe.window
  -> 运行子应用 JavaScript
  -> 提供独立的 history、location 和全局对象

Web Component + Shadow Root
  -> 保存子应用 DOM
  -> 保存子应用 CSS
  -> 显示子应用页面

document 代理
  -> 连接 iframe 和 Shadow Root
```

路由、运行模式、生命周期、通信和样式隔离都建立在这套结构上。

## 2. 主应用接入

### 2.1 核心包与框架适配包

Vue 3 主应用安装：

```bash
pnpm add wujie wujie-vue3
```

| 包 | 职责 |
| --- | --- |
| `wujie` | 提供 iframe 沙箱、Shadow Root、资源加载、实例、路由、通信、预加载和缓存等核心能力 |
| `wujie-vue3` | 将核心能力适配为 Vue 3 插件和组件 |

核心包不依赖 Vue，可以直接提供：

```js
import {
  bus,
  setupApp,
  startApp,
  preloadApp,
  destroyApp,
  refreshApp,
  clearAssetsCache,
} from "wujie";
```

Vue 适配包提供组件化接入：

```vue
<WujieVue
  name="order"
  url="http://localhost:5174/list"
  :alive="true"
  :sync="true"
/>
```

`wujie-vue3` 安装在 Vue 3 主应用中，不要求所有 Vue 子应用安装。

### 2.2 注册 Vue 插件

`main.js`：

```js
import WujieVue from "wujie-vue3";

createApp(App)
  .use(router)
  .use(WujieVue)
  .mount("#app");
```

### 2.3 应用配置

`micro-apps.js`：

```js
export const microApps = {
  order: {
    name: "order",
    url: "http://localhost:5174/list",
    alive: true,
  },
  finance: {
    name: "finance",
    url: "http://localhost:5175/settlement",
    alive: false,
  },
};
```

| 字段 | 作用 |
| --- | --- |
| `name` | 无界实例标识、路由同步参数名、缓存和复用边界 |
| `url` | 子应用资源基准地址和初始子路由 |
| `alive` | 决定实例、DOM、路由和状态的生命周期 |

### 2.4 `setupApp`、`preloadApp` 和应用启动

```js
setupApp({
  name: app.name,
  url: app.url,
  alive: app.alive,
  sync: true,
  props: operatorContext,
  fetch: fetchMicroResource,
});
```

三个操作的职责不同：

```txt
setupApp
  -> 保存应用默认配置
  -> 不加载和渲染页面

preloadApp
  -> 在空闲阶段准备资源或预执行应用

<WujieVue> / startApp
  -> 在指定容器中启动并显示应用
```

`setupApp` 不会根据主应用路由自动激活子应用。页面显示仍由主应用路由和组件渲染控制。

### 2.5 组件参数

```vue
<WujieVue
  name="order"
  :url="appUrls.order"
  :alive="true"
  :sync="true"
  :props="operatorContext"
  :fetch="fetchMicroResource"
/>
```

| 参数 | 作用 |
| --- | --- |
| `name` | 标识无界实例 |
| `url` | 指定子应用入口和初始路由 |
| `alive` | 选择保活或非保活模式 |
| `sync` | 同步子应用路由 |
| `props` | 提供初始化上下文 |
| `fetch` | 控制资源请求 |
| 生命周期 | 记录运行过程并转换页面状态 |

### 2.6 跨域资源

无界需要从子应用地址获取 HTML、JavaScript 和 CSS。开发服务器或生产网关必须允许主应用加载这些资源。

Webpack 开发服务器：

```js
headers: {
  "Access-Control-Allow-Origin": "*",
}
```

Vite 开发服务器：

```js
server: {
  headers: {
    "Access-Control-Allow-Origin": "*",
  },
}
```

iframe 沙箱不能绕过浏览器跨域限制。生产环境应按真实域名、Cookie、凭证和安全策略配置 CORS。

## 3. Vite 与原生 ESM

### 3.1 ESM 的执行环境

Vite 开发态使用浏览器原生 ESM。原生模块具有独立的模块图、地址解析、异步加载和模块作用域，不能直接当作普通脚本文本放进 `with` 或 `Function` 中执行。

无界让模块在 iframe 的浏览器环境中执行：

```txt
原生 ESM
  -> iframe 中的模块加载器
  -> iframe.window 中执行
  -> document 代理操作 Shadow Root
```

这种方式不需要将 ESM 强制降级成普通脚本，但仍需处理生命周期时序和 `location` 语义。

### 3.2 Vite 单例应用的主动挂载

单例模式需要子应用提供挂载和卸载函数：

```jsx
let root;

function mount() {
  if (root) return;

  root = createRoot(document.querySelector("#app"));
  root.render(
    <BrowserRouter>
      <FinanceApp />
    </BrowserRouter>,
  );
}

function unmount() {
  root?.unmount();
  root = undefined;
}
```

向无界注册生命周期：

```jsx
if (window.__POWERED_BY_WUJIE__) {
  window.__WUJIE_MOUNT = mount;
  window.__WUJIE_UNMOUNT = unmount;
  window.__WUJIE.mount();
} else {
  mount();
}
```

原生 ESM 异步加载入口和依赖，生命周期函数可能晚于无界的首次挂载时机才完成定义。

```txt
无界执行子应用
  -> ESM 异步加载模块
  -> 子应用定义 __WUJIE_MOUNT
  -> 子应用调用 window.__WUJIE.mount()
  -> 无界执行挂载函数
```

`window.__WUJIE.mount()` 用于补上异步生命周期的挂载时机，无界负责处理重复挂载状态。

### 3.3 `$wujie.location`

子应用 JavaScript 在 iframe 中运行，因此 `window.location` 首先属于 iframe。原生 ESM 不能完全使用普通脚本的闭包方式代理 `location`。

需要读取子应用业务地址时使用：

```js
window.$wujie.location.host;
```

以下代码需要检查地址语义：

- 根据 `location.host` 判断环境
- 拼接接口域名
- 使用 `location.href` 跳转
- 根据 `origin` 决定登录域
- 第三方 SDK 读取当前地址

## 4. 路由同步

### 4.1 三层路由状态

微前端页面可能同时存在：

```txt
主应用路由
  /micro/order
  /micro/finance

订单子应用路由
  /list
  /exceptions

财务子应用路由
  /settlement
  /invoices
```

子应用运行在 iframe 的 `history` 和 `location` 中，浏览器地址栏只显示主应用地址。

### 4.2 `sync` 的作用

```vue
<WujieVue
  name="order"
  :sync="true"
/>
```

`sync` 将子应用的 `path + query + hash` 编码到主应用 URL 的查询参数中，参数名来自子应用 `name`。

```txt
主应用页面：/micro/order
子应用页面：/exceptions?level=high

同步后的主应用地址：
/micro/order?order=%2Fexceptions%3Flevel%3Dhigh
```

查询参数保存的是子应用路由快照，可用于：

- 页面刷新后恢复子应用位置
- 浏览器前进后退时保留子应用位置
- 复制主应用 URL 时携带子应用路由

### 4.3 主应用切换时保留查询参数

```js
function switchApp(appName) {
  const search = window.location.search;
  router.push(`${microApps[appName].route}${search}`);
}
```

主应用切换菜单时删除 `search`，会同时删除无界保存的子应用路由状态，导致刷新和恢复异常。

### 4.4 同步边界

无界实例初次创建时从主应用 URL 读取子路由。实例创建后，主要由子应用向主应用 URL 同步。

```txt
实例初次创建
  -> 主应用 URL 恢复子应用路由

实例运行期间
  -> 子应用路由同步到主应用 URL
```

`sync` 不是永久的双向响应式绑定。保活实例已经存在时，只修改主应用查询参数或组件 `url`，不一定会立即改变子应用内部路由，此时需要通过路由通信主动跳转。

## 5. 运行模式

无界根据 `alive` 和子应用是否提供生命周期函数形成三种运行模式。

| 模式 | 条件 | 离开时 | 再次进入时 | 状态结果 |
| --- | --- | --- | --- | --- |
| 保活模式 | `alive: true` | Web Component 离开容器但实例保留 | Web Component 重新插入容器 | DOM、路由、输入和框架状态保留 |
| 单例模式 | `alive: false` 且提供 `mount/unmount` | 卸载框架页面实例 | 重新挂载页面实例 | iframe 和无界实例可复用，页面状态重建 |
| 重建模式 | `alive: false` 且没有 `mount/unmount` | 销毁页面、iframe 和无界实例 | 全量重新创建 | 运行状态不保留 |

### 5.1 保活模式

```js
order: {
  name: "order",
  alive: true,
}
```

保活模式保留：

```txt
子应用实例
Web Component 和 DOM
iframe 运行环境
子应用路由
输入和页面状态
```

离开和返回主要触发：

```txt
deactivated
activated
```

保活应用离开页面后仍然存在，因此可能继续运行：

- 定时器
- EventBus 监听
- 后台数据请求
- 内存中的业务状态

保活适用于高频往返、复杂表单或恢复状态价值较高的页面，不适合作为所有应用的默认配置。

### 5.2 单例模式

```js
finance: {
  name: "finance",
  alive: false,
}
```

同时提供：

```js
window.__WUJIE_MOUNT = mount;
window.__WUJIE_UNMOUNT = unmount;
```

单例模式离开时销毁框架页面实例，iframe、无界实例和资源缓存仍可复用。再次进入时重新执行 `mount`。

```txt
首次进入
  -> beforeLoad
  -> beforeMount
  -> afterMount

离开
  -> beforeUnmount
  -> afterUnmount

再次进入
  -> beforeMount
  -> afterMount
```

### 5.3 重建模式

```txt
alive = false
+
没有 mount / unmount
=
重建模式
```

离开时销毁：

```txt
页面 DOM
Web Component
iframe
无界实例
子应用框架实例
```

再次进入时重新执行资源加载和实例创建链路。

## 6. 生命周期

生命周期与运行模式相关，不是所有应用都会触发全部钩子。

| 生命周期 | 含义 | 主要场景 |
| --- | --- | --- |
| `beforeLoad` | 开始加载静态资源 | 首次加载或清缓存重建 |
| `beforeMount` | 调用子应用 `mount` 前 | 单例模式 |
| `afterMount` | 调用子应用 `mount` 后 | 单例模式 |
| `beforeUnmount` | 调用子应用 `unmount` 前 | 单例应用离开或销毁 |
| `afterUnmount` | 调用子应用 `unmount` 后 | 单例应用离开或销毁 |
| `activated` | 保活应用进入容器 | 保活模式 |
| `deactivated` | 保活应用离开容器 | 保活模式 |
| `loadError` | 子应用资源加载失败 | 网络、地址或资源异常 |

```txt
保活模式
首次进入：beforeLoad -> activated
离开：deactivated
返回：activated

单例模式
首次进入：beforeLoad -> beforeMount -> afterMount
离开：beforeUnmount -> afterUnmount
返回：beforeMount -> afterMount
```

没有提供 `mount/unmount` 的应用不会触发相关挂载钩子；非保活应用不会触发 `activated/deactivated`。

## 7. 应用通信

无界提供三种常见通信方式：

```txt
props
EventBus
window
```

`window.parent` 和 iframe `contentWindow` 会让业务代码依赖容器结构和全局变量，不适合作为普通业务通信的默认方式。

### 7.1 `props` 初始化上下文

主应用传入：

```vue
<WujieVue :props="operatorContext" />
```

子应用读取：

```js
const context = window.$wujie?.props;
```

`props` 适合：

- 当前用户基础信息
- 角色、权限和租户信息
- 应用启动参数
- 主应用提供的业务方法

`props` 用于提供上下文，不等同于完整的全局状态管理器。

### 7.2 EventBus 运行期通信

主应用发送，子应用接收：

```js
bus.$emit("host:operation-notice", notice);
```

```js
window.$wujie?.bus.$on(
  "host:operation-notice",
  receiveOperationNotice,
);
```

子应用发送，主应用接收：

```js
window.$wujie?.bus.$emit("order:exception-reviewed", {
  count,
  operator: hostContext.name,
});
```

```js
bus.$on(
  "order:exception-reviewed",
  receiveExceptionReview,
);
```

监听与清理必须使用同一个函数引用：

```js
bus.$on(eventName, handler);
bus.$off(eventName, handler);
```

保活应用离开容器后监听仍可能存在。单例应用应在 `unmount` 或组件清理函数中移除监听。

## 8. 隔离边界

### 8.1 JavaScript 隔离

每个子应用的 JavaScript 运行在独立的 iframe.window 中，以下对象天然分开：

```txt
window 全局变量
history
location
定时器所属 window
全局事件监听
```

iframe 不是绝对安全边界：

- 无界会将 iframe document 代理到 Shadow Root
- 主子应用可以通过 props、EventBus 和 `parent` 通信
- 同源 iframe 之间可能访问彼此对象
- 第三方库可能依赖 window 和 DOM 属于同一 document

### 8.2 DOM 隔离

```txt
子应用 JavaScript -> iframe
子应用 DOM        -> Web Component 的 Shadow Root
```

子应用执行：

```js
document.querySelector("#app");
```

无界代理后的 `document` 会查询当前子应用的 Shadow Root。

第三方组件异常时需要检查：

- 依赖 `document.body` 的弹窗和 Portal
- 向 `head` 动态插入样式或脚本
- 依赖 `ownerDocument` 的组件
- 监听 `document` 滚动的组件
- 从元素向上查找 window 的定位库

### 8.3 CSS 隔离

子应用 DOM 位于 Shadow Root，主应用普通选择器不能跨过 Shadow DOM 边界：

```css
.finance-app h2 {
  color: red;
}
```

该选择器无法直接匹配 Shadow Root 中的子应用节点。

Shadow DOM 也不是绝对视觉隔离：

- 可继承属性可能从宿主继承
- CSS 自定义属性可以跨宿主边界传入
- 字体和浏览器默认样式仍会影响结果
- Portal 挂到其他容器后可能离开当前 Shadow Root

## 9. 预加载、预执行与缓存

### 9.1 预加载配置

```js
preloadApp({
  name: microApps.finance.name,
  exec: false,
});
```

| 配置 | 行为 | 优势 | 代价 |
| --- | --- | --- | --- |
| `exec: false` | 提前加载 HTML、JavaScript 和 CSS | 减少首次进入的网络等待 | 首次进入时仍需执行和渲染 |
| `exec: true` | 加载资源后继续预执行应用 | 正式进入时接近立即显示 | 提前占用 CPU、请求接口并产生运行副作用 |

`exec: true` 需要评估：

- 是否抢占主应用首屏网络和 CPU
- 是否提前请求暂时不需要的接口
- 是否依赖尚未准备好的 `props`
- 是否提前注册监听和定时器
- 是否产生埋点、权限检查或其他业务副作用

### 9.2 配置一致性

预加载和正式启动必须共享关键配置：

```txt
name
url
alive
fetch
replace
degrade
```

可以使用 `setupApp()` 集中保存默认配置，再通过应用 `name` 执行预加载，避免重复参数不一致。

配置不一致可能导致预加载结果无法复用，或应用实例采用错误的运行方式。

### 9.3 三种状态的差异

| 能力 | 保留内容 | 不代表 |
| --- | --- | --- |
| 资源缓存 | HTML、JavaScript、CSS 等加载结果 | 页面实例仍然存活 |
| 预加载 | 用户进入前准备资源 | 页面已经完成渲染 |
| 保活 | 子应用实例、DOM、路由和状态 | 不占用内存或没有后台副作用 |

完整重新加载需要同时处理缓存和实例：

```js
clearAssetsCache(appOrigin);
await destroyApp(appName);
```

## 10. 工程兜底

### 10.1 自定义资源请求

```js
export async function fetchMicroResource(input, init) {
  return window.fetch(input, init);
}
```

自定义 `fetch` 可以用于：

- 统一携带凭证
- 增加请求头
- 统计资源加载耗时
- 处理静态资源鉴权
- 切换灰度资源地址
- 实现重试和错误上报

请求异常必须继续抛出。吞掉异常会导致 `loadError` 和页面兜底层无法获得真实失败状态。

### 10.2 生命周期状态机

框架生命周期需要转换为用户可见状态：

```txt
beforeLoad / beforeMount
  -> loading

afterMount / activated
  -> success

loadError
  -> error

用户重试
  -> retry
```

```js
function recordLifecycle(appName, lifecycle) {
  if (["beforeLoad", "beforeMount"].includes(lifecycle)) {
    loadingApps[appName] = true;
  }

  if (["afterMount", "activated"].includes(lifecycle)) {
    loadingApps[appName] = false;
    clearFailure(appName);
  }
}
```

资源失败：

```js
function handleLoadError(appName, url, error) {
  loadingApps[appName] = false;
  appFailures[appName] = {
    url,
    message: error?.message || "子系统资源加载失败",
  };
}
```

### 10.3 失败与重试

加载失败状态需要包含：

```txt
明确的错误提示
失败资源或应用信息
重试入口
其他子系统的导航入口
监控和错误上报信息
```

重试过程：

```txt
恢复正确资源地址
  -> 清理失败状态
  -> 清理缓存和旧实例
  -> 重建应用
  -> 等待 afterMount 或 activated
```

工程兜底需要保证子应用失败时主应用壳、导航和其他子应用仍可使用。

## 11. 框架运行模型对比

| 维度 | qiankun | MicroApp | 无界 |
| --- | --- | --- | --- |
| 接入模型 | 应用注册、路由激活和生命周期协议 | Custom Element 驱动加载 | 组件或 API 启动无界实例 |
| JavaScript 环境 | 主要使用 Proxy 沙箱 | with 沙箱或可选 iframe | iframe 原生 window |
| DOM 位置 | 主应用容器 | Custom Element 内部 | Web Component 的 Shadow Root |
| CSS 隔离 | 需要选择隔离策略 | 常见为选择器作用域改写 | Shadow DOM 边界 |
| Vite/ESM | 通常需要额外适配 | 可通过 iframe 模式处理 | ESM 在 iframe 中执行，需处理挂载时序和 location |
| 路由 | activeRule、base 和项目方案 | router-mode、baseroute | `sync` 将子路由编码到主应用 query |
| 保活 | 容器常驻或项目方案 | `keep-alive` | `alive` 控制实例和 Web Component 热插拔 |
| 非保活 | 生命周期卸载 | 标签卸载或销毁 | 生命周期决定单例或重建模式 |
| 通信 | props、全局状态等 | 定向和全局数据中心 | props、window、EventBus |
| 预加载 | prefetch | preFetch | preload 与预执行分开 |

## 12. 使用边界

- Vite 子应用可以执行原生 ESM，但单例模式需要处理异步生命周期的主动挂载。
- iframe 中的 `window.location` 不完全等同于子应用业务地址，地址判断需要关注 `$wujie.location`。
- `sync` 保存子应用路由快照，不是永久双向绑定。
- `alive: false` 不一定销毁 iframe，是否提供 `mount/unmount` 决定单例或重建模式。
- `exec: false` 只预加载资源，`exec: true` 才会预执行应用。
- 保活应用离开容器后，定时器、监听和后台任务仍可能运行。
- Shadow Root 阻止普通选择器穿透，但继承属性、CSS 变量、字体和 Portal 仍可能影响显示。
- `loadError` 只是错误信号，完整兜底还需要失败页面、状态清理、重试入口和监控信息。

完整关系：

```txt
无界实例
  ├── iframe.window
  │     ├── JavaScript
  │     └── history / location
  │
  └── Web Component
        └── Shadow Root
              ├── DOM
              └── CSS

路由：sync 保存子应用路由快照
模式：alive + 生命周期决定保活、单例或重建
通信：props 提供上下文，EventBus 处理运行期事件
预热：preload 准备资源，exec 决定是否预执行
兜底：生命周期信号转换为 loading、success、error 和 retry
```
