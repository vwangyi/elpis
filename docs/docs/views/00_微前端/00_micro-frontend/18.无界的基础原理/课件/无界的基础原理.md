# 17. 无界的基础原理

## 1. 运行环境与显示环境

无界没有把完整的子应用页面放进 iframe，而是将子应用拆分到两个区域：

```txt
iframe
  -> 运行子应用 JavaScript
  -> 提供独立的 window、history、location

Web Component + Shadow Root
  -> 保存子应用 DOM
  -> 保存子应用 CSS
  -> 显示子应用页面
```

两个区域通过 iframe `document` 的代理连接：

```txt
iframe 中的 JavaScript
  -> 调用 document DOM API
  -> document 代理把操作转向 Shadow Root
  -> 查询或修改子应用的真实 DOM
```

核心关系：

```txt
iframe.window：JavaScript 运行环境
Shadow Root：DOM 和 CSS 显示区域
document 代理：运行环境与显示区域之间的桥
```

## 2. 无界与 qiankun 的差异

两者都可以使用 HTML Entry 获取并解析子应用资源，主要区别在资源解析后的去向和 JavaScript 沙箱的实现方式。

| 内容 | qiankun | 无界 |
| --- | --- | --- |
| DOM | 主应用普通容器 | Web Component 的 Shadow Root |
| CSS | 主应用容器及样式隔离机制 | Shadow Root |
| JavaScript | Proxy 沙箱 | iframe 原生 window |
| DOM 操作 | 沙箱中的代理对象访问主应用容器 | iframe document 代理到 Shadow Root |

```txt
qiankun
  -> DOM、CSS 放入主应用容器
  -> JavaScript 在 Proxy 沙箱中执行

无界
  -> DOM、CSS 放入 Shadow Root
  -> JavaScript 在 iframe.window 中执行
```

Shadow Root 提供 DOM 和 CSS 边界，iframe 提供独立的 JavaScript 全局环境。

## 3. Web Component 显示区域

主应用使用自定义元素声明子应用容器：

```html
<mini-app name="order"></mini-app>
```

注册自定义元素：

```js
customElements.define("mini-app", MiniAppElement);
```

元素进入页面后触发 `connectedCallback()`：

```js
connectedCallback() {
  this.start();
}
```

自定义元素创建 Shadow Root：

```js
constructor() {
  super();
  this.attachShadow({ mode: "open" });
}
```

Shadow Root 内部保存子应用结构：

```js
this.shadowRoot.innerHTML = `
  <mini-app-head></mini-app-head>
  <mini-app-body>
    <div id="app"></div>
  </mini-app-body>
`;
```

| 节点 | 作用 |
| --- | --- |
| `mini-app-head` | 保存子应用样式 |
| `mini-app-body` | 保存子应用 body 内容和动态节点 |
| `#app` | Vue、React 等框架的挂载节点 |

## 4. iframe 运行环境

运行时创建隐藏的同源 iframe：

```js
const iframe = document.createElement("iframe");
iframe.hidden = true;
iframe.srcdoc = "<!doctype html><html><head></head><body></body></html>";
this.appendChild(iframe);
```

iframe 加载后可以取得独立的全局环境：

```js
const frameWindow = iframe.contentWindow;
const frameDocument = iframe.contentDocument;
```

```txt
frameWindow
frameDocument
frameWindow.history
frameWindow.location
frameWindow.setTimeout
frameWindow.Promise
```

这些对象属于 iframe，不属于主应用 window。浏览器原生 iframe 已经提供独立 window，不需要通过 `new Proxy(window, ...)` 模拟另一套全局对象。

此时 JavaScript 和 DOM 仍然处于两个不同位置：

```txt
子应用 JavaScript -> iframe
子应用 #app       -> Shadow Root
```

未建立代理时，下面的查询只能访问 iframe 自己的 DOM，无法找到 Shadow Root 中的 `#app`：

```js
frameDocument.querySelector("#app");
```

## 5. iframe document 代理

### 5.1 查询代理

保存 iframe 原来的查询方法：

```js
const rawQuerySelector =
  frameDocument.querySelector.bind(frameDocument);
```

将查询优先转向 Shadow Root：

```js
frameDocument.querySelector = (selector) =>
  this.shadowRoot.querySelector(selector) ||
  rawQuerySelector(selector);
```

代理后的查询链路：

```txt
document.querySelector("#app")
  -> iframe document 的代理方法
  -> shadowRoot.querySelector("#app")
  -> 返回 Shadow Root 中的真实节点
```

Vue、React 仍然可以使用普通挂载代码：

```js
createApp(App).mount("#app");
```

常见查询代理包括：

```txt
querySelector
querySelectorAll
getElementById
getElementsByTagName
getElementsByClassName
getElementsByName
head
body
```

### 5.2 样式插入代理

子应用开发环境可能使用 JavaScript 动态插入样式：

```js
const style = document.createElement("style");
document.head.appendChild(style);
```

样式插入 iframe 的 head 时，无法作用于 Shadow Root 中的 DOM。`head.appendChild` 需要将样式节点转向 Shadow Root：

```js
frameDocument.head.appendChild = (node) =>
  node instanceof frameDocument.defaultView.HTMLStyleElement
    ? shadowHead.appendChild(node)
    : rawHeadAppendChild(node);
```

```txt
style  -> Shadow Root 中的 mini-app-head
script -> iframe head
```

### 5.3 动态节点插入代理

弹窗、提示和下拉菜单经常插入 `document.body`：

```js
document.body.appendChild(node);
```

节点插入隐藏 iframe 的 body 时无法显示。`body.appendChild` 需要将节点转向 Shadow Root：

```js
frameDocument.body.appendChild = (node) =>
  shadowBody.appendChild(node);
```

`insertBefore` 等动态插入方法也需要采用相同的代理方式。

### 5.4 节点创建代理

框架运行在 iframe 中，但业务 DOM 最终位于主应用的 Shadow Root。普通业务节点可以由主应用 document 创建：

```js
frameDocument.createElement = (tagName, options) =>
  tagName.toLowerCase() === "script"
    ? rawCreateElement(tagName, options)
    : mainDocument.createElement(tagName, options);
```

```txt
script 节点 -> iframe document 创建，在 iframe 中执行
普通节点   -> 主应用 document 创建，进入 Shadow Root
```

这样可以减少节点所属 document、事件和跨运行环境操作产生的问题。

## 6. JavaScript 在 iframe 中执行

直接在主应用中调用子应用入口函数，函数仍然使用主应用的 `window` 和 `document`。

将入口代码作为 script 插入 iframe document：

```js
const script = frameDocument.createElement("script");
script.type = "module";
script.textContent = `(${childApplication.toString()})()`;
frameDocument.head.appendChild(script);
```

此时入口代码中的全局对象来自 iframe：

```txt
window   -> iframe.window
document -> iframe.document
history  -> iframe.history
location -> iframe.location
```

完整调用链：

```txt
子应用代码在 iframe.window 中执行
  -> 调用 iframe.document.querySelector("#app")
  -> document 代理查询 Shadow Root
  -> 返回 Shadow Root 中的真实 DOM
  -> 子应用修改真实 DOM
  -> 主应用页面显示更新结果
```

真实业务 DOM 只有一份，位于 Shadow Root。iframe 只保存运行环境，不保存另一份业务页面。

框架首次取得真实节点后，后续状态更新会继续操作同一批节点：

```txt
iframe.window 中的框架实例
  -> 持有 Shadow Root 中的 DOM Node
  -> 状态变化
  -> 修改 DOM Node
  -> 页面更新
```

## 7. HTML Entry 加载

远程子应用通常返回 HTML 入口：

```html
<!doctype html>
<html>
  <head>
    <link rel="stylesheet" href="style.css" />
  </head>
  <body>
    <div id="app"></div>
    <script type="module" src="main.js"></script>
  </body>
</html>
```

加载过程：

```txt
获取子应用 HTML
  -> 解析 HTML、CSS 和 JavaScript
  -> body HTML 和 CSS 放入 Shadow Root
  -> module script 放入 iframe document
  -> module 在 iframe.window 中执行
  -> iframe.document 代理到 Shadow Root
  -> 框架找到 #app 并完成渲染
```

资源分流：

```txt
子应用 HTML Entry
  ├── DOM、CSS       -> Shadow Root
  └── JavaScript     -> iframe.window
                           |
                           v
                    iframe.document 代理
                           |
                           v
                      Shadow Root DOM
```

## 8. 最小实现的模块职责

| 文件 | 作用 |
| --- | --- |
| `App.vue` | 声明 `<mini-wujie>` 及其接入参数 |
| `main.js` | 启动运行时 |
| `index.js` | 暴露启动入口 |
| `element.js` | 注册自定义元素并创建 Shadow Root |
| `source.js` | 获取和解析 HTML Entry |
| `app.js` | 组织加载、挂载和销毁过程 |
| `iframe-runtime.js` | 创建 iframe、代理 document、执行脚本和同步路由 |

接入参数：

```html
<mini-wujie
  name="order"
  url="http://localhost:5174/"
  baseurl="/micro/order"
  default-path="/micro/order/list"
></mini-wujie>
```

| 属性 | 含义 |
| --- | --- |
| `name` | 子应用名称 |
| `url` | 子应用 HTML 入口 |
| `baseurl` | 子应用路由前缀 |
| `default-path` | iframe 初始路由 |

HTML 解析结果：

```js
{
  bodyHtml,
  inlineStyles,
  styleLinks,
  moduleScripts,
}
```

运行时将结构和样式放入 Shadow Root：

```js
body.innerHTML = entry.bodyHtml || '<div id="app"></div>';
appendEntryStyles(head, entry);
```

module script 放入 iframe：

```js
const element = frameDocument.createElement("script");
element.type = "module";
element.src = script.src;
frameDocument.head.appendChild(element);
```

## 9. iframe 路由与主应用地址

iframe 和主应用拥有两套独立的 history：

| 所属页面 | location | history |
| --- | --- | --- |
| 主应用 | `window.location` | `window.history` |
| iframe 子应用 | `frameWindow.location` | `frameWindow.history` |

子应用 Router 调用 `history.pushState()` 时，修改的是 iframe 地址。浏览器地址栏显示的是主应用地址，因此不会自动变化。

```txt
子应用 Router 切换路由
  -> 修改 frameWindow.history
  -> iframe 路由发生变化
  -> 主应用 window.history 不变
  -> 浏览器地址栏不变
```

`document` 代理只处理 DOM 操作，无法同步 `window.history` 和 `window.location`。

最小路由同步需要处理：

```txt
初始化 iframe 时恢复当前路径
包装 iframe.history.pushState
包装 iframe.history.replaceState
监听 iframe popstate
将 iframe 地址写入主应用 history
销毁时恢复原方法和事件监听
```

初始路径可以从当前主应用地址或默认路径中确定：

```js
function getInitialPath(app) {
  const { pathname, search, hash } = window.location;
  const isCurrentApp =
    pathname === app.baseurl ||
    pathname.startsWith(`${app.baseurl}/`);

  return isCurrentApp
    ? `${pathname}${search}${hash}`
    : app.defaultPath;
}
```

包装 iframe history：

```js
const rawPushState =
  frameHistory.pushState.bind(frameHistory);

frameHistory.pushState = (...args) => {
  const result = rawPushState(...args);
  syncUrl();
  return result;
};
```

执行顺序必须是先修改 iframe 地址，再读取新地址并同步到主应用。

地址同步：

```js
function syncUrl() {
  const isCurrentApp =
    window.location.pathname === app.baseurl ||
    window.location.pathname.startsWith(`${app.baseurl}/`);

  if (!isCurrentApp) return;

  const { pathname, search, hash } = frameWindow.location;
  const childUrl = `${pathname}${search}${hash}`;

  window.history.replaceState(
    window.history.state,
    "",
    childUrl,
  );

  window.dispatchEvent(
    new PopStateEvent("popstate", {
      state: window.history.state,
    }),
  );
}
```

判断当前激活应用可以避免旧 iframe 在销毁过程中覆盖新应用地址。主动派发 `popstate` 用于通知主应用 Router 更新内部状态。

销毁时恢复环境：

```js
return () => {
  frameHistory.pushState = rawPushState;
  frameHistory.replaceState = rawReplaceState;
  frameWindow.removeEventListener("popstate", syncUrl);
};
```

教学实现使用主应用 `replaceState()` 展示单应用地址同步，不包含多应用同时激活、完整前进后退、query 编码、保活和路由还原等情况。

## 10. 完整加载链路

```txt
注册自定义元素
  -> 主应用渲染 <mini-wujie>
  -> 创建 Shadow Root
  -> 获取并解析子应用 HTML
  -> DOM、CSS 进入 Shadow Root
  -> 创建同源隐藏 iframe
  -> 设置 iframe 初始路由
  -> 代理 iframe document
  -> module script 在 iframe.window 中执行
  -> 框架通过 document 代理挂载到 Shadow Root
  -> 子应用页面显示
```

最终结构：

```txt
MiniWujieInstance
  ├── Web Component
  │     └── Shadow Root
  │           ├── DOM
  │           └── CSS
  │
  └── iframe
        ├── window
        ├── history / location
        └── 子应用 JavaScript

iframe.document DOM API
  -> document 代理
  -> Shadow Root
```

## 11. 实现边界

- iframe 与 Shadow Root 是并列结构，iframe 不负责显示子应用页面。
- 真实业务 DOM 只有一份，位于 Shadow Root。
- Shadow Root 不是 JavaScript 沙箱，JavaScript 隔离来自 iframe.window。
- iframe 和 Web Component 不会自动连接，连接依赖 document 代理。
- 同源 iframe 和 DOM 代理用于微前端运行时隔离，不是执行不可信代码的安全边界。
- 最小实现只覆盖核心加载链路和单应用路由同步，不等同于完整的无界实现。
- 完整框架还需要处理通信、保活、预加载、预执行、多应用路由、更多 DOM API 和兼容补丁。

无界的基础原理可以归纳为：

```txt
运行环境和显示环境分离
  -> JavaScript 在 iframe.window 中运行
  -> DOM、CSS 在 Shadow Root 中显示
  -> iframe.document 代理重新连接两者
```
