# 15. CustomElement 加载子应用

## 1. 核心思路

类 MicroApp 的接入模型：

```txt
使用 Custom Element 作为子应用容器
  +
使用 HTML Entry 加载远程子应用
```

主应用通过自定义标签声明子应用：

```html
<micro-app
  name="order"
  url="http://localhost:5174/"
  baseurl="/micro/order"
></micro-app>
```

| 属性      | 作用                                   |
| --------- | -------------------------------------- |
| `name`    | 子应用标识，用于实例、缓存、通信和隔离 |
| `url`     | 子应用入口 HTML 地址                   |
| `baseurl` | 主应用分配给子应用的路由前缀           |

浏览器不会因为看到 `<micro-app>` 就自动加载子应用。框架必须先注册对应的 Custom Element 类。

## 2. 完整加载链路

```txt
主应用注册 micro-app 标签
  -> 主应用渲染 micro-app 标签
  -> connectedCallback 触发
  -> 读取 name、url、baseurl
  -> 创建 MicroAppInstance
  -> 请求子应用 index.html
  -> 解析 DOM、CSS 和 JavaScript
  -> 补全资源地址
  -> 插入子应用 DOM 和样式
  -> 执行子应用入口脚本
  -> Vue 或 React 渲染业务页面
```

标签从页面移除时：

```txt
disconnectedCallback
  -> 卸载当前实例
  -> 清空子应用 DOM
  -> 派发 unmount 事件
  -> 按需删除实例缓存
```

## 3. 注册自定义标签

主应用启动加载器：

```js
import { defineElement } from "./element.js";

export const SimpleMicroApp = {
  start() {
    defineElement();
  },
};
```

```js
import { SimpleMicroApp } from "./micro-app/index.js";

SimpleMicroApp.start();
```

注册 `<micro-app>`：

```js
export function defineElement() {
  if (!window.customElements.get("micro-app")) {
    window.customElements.define("micro-app", MicroAppElement);
  }
}
```

同一个自定义标签不能重复注册，因此调用 `customElements.define()` 前需要检查。

## 4. 标签生命周期触发加载

`<micro-app>` 插入文档后，浏览器自动调用 `connectedCallback()`。

```js
class MicroAppElement extends HTMLElement {
  connectedCallback() {
    const name = this.getAttribute("name");
    const url = this.getAttribute("url");
    const baseurl = this.getAttribute("baseurl");

    const app = new MicroAppInstance({
      name,
      url,
      baseurl,
      container: this,
    });

    this.app = app;
    app.load();
  }

  disconnectedCallback() {
    this.app?.unmount();
  }
}
```

类 MicroApp 由标签生命周期触发加载；qiankun 通常由路由匹配 `activeRule` 后触发加载。

```txt
qiankun   -> 注册应用
MicroApp  -> 使用组件
```

二者是不同的接入模型。

## 5. 微应用实例

一个 `<micro-app>` 标签对应一个 `MicroAppInstance`。

```js
class MicroAppInstance {
  constructor({ name, url, baseurl, container }) {
    this.name = name;
    this.url = url;
    this.baseurl = baseurl;
    this.container = container;
    this.status = "created";
    this.source = null;
    this.proxyWindow = createScopedWindow(this);
  }
}
```

| 字段          | 作用                                         |
| ------------- | -------------------------------------------- |
| `name`        | 标识当前子应用                               |
| `url`         | 请求子应用入口 HTML                          |
| `baseurl`     | 提供子应用路由前缀                           |
| `container`   | 保存当前 `<micro-app>` 元素                  |
| `status`      | 记录 created、loading、mounted、error 等状态 |
| `source`      | 保存解析后的 HTML、CSS 和脚本                |
| `proxyWindow` | 为子应用提供受控的 `window` 和 `document`    |

创建实例只保存加载所需信息，调用 `load()` 才会开始请求资源。

```js
async load() {
  this.status = 'loading'
  this.container.dispatchEvent(createLifeCycleEvent('created', this))

  try {
    await loadHtml(this)
    this.mount()
  } catch (error) {
    this.status = 'error'
    this.container.dispatchEvent(
      createLifeCycleEvent('error', this, { error }),
    )
    throw error
  }
}
```

```txt
loadHtml -> 准备 HTML、CSS 和 JavaScript
mount    -> 将资源放入容器并执行入口脚本
```

## 6. HTML Entry

`url` 指向子应用的 `index.html`。加载器把 HTML 当作资源入口，而不是跳转目标。

```js
async function loadHtml(app) {
  const htmlText = await fetch(app.url).then((response) => response.text());
  app.source = await parseHtmlEntry(htmlText, app.url);
}
```

加载器需要完成：

1. 请求入口 HTML。
2. 解析 DOM 结构。
3. 提取 `<link>`、`<style>` 和 `<script>`。
4. 补全 CSS 和 JavaScript 地址。
5. 请求外部资源。
6. 将解析结果交给实例挂载。

不能只把 HTML 字符串写入 `innerHTML`：

- 通过 `innerHTML` 插入的脚本不会按预期自动执行。
- 相对资源路径可能按主应用地址解析，导致资源请求错误。
- 加载器无法统一处理样式、沙箱、错误和缓存。

## 7. 模拟子应用的 `head` 和 `body`

主应用已经拥有自己的 `<html>`、`<head>` 和 `<body>`，子应用不能再插入一套同级文档结构。

加载器将：

```txt
head -> micro-app-head
body -> micro-app-body
```

转换后的结构：

```html
<micro-app name="order">
  <micro-app-head></micro-app-head>
  <micro-app-body>
    <div id="app"></div>
  </micro-app-body>
</micro-app>
```

`micro-app-head` 保存子应用样式，`micro-app-body` 保存子应用页面结构。

## 8. 资源地址补全

子应用入口可能包含：

```html
<script type="module" src="/src/main.js"></script>
```

主应用地址是 `http://localhost:5173/`，子应用地址是 `http://localhost:5174/`。如果按主应用地址解析，脚本会被错误地请求为：

```txt
http://localhost:5173/src/main.js
```

正确地址是：

```txt
http://localhost:5174/src/main.js
```

可以使用 `URL` 补全资源地址：

```js
function resolveAssetUrl(assetPath, entryUrl) {
  return new URL(assetPath, entryUrl).href;
}
```

CSS、JavaScript、图片和字体等相对路径都需要基于子应用入口地址解析。

## 9. 挂载 DOM、样式和脚本

```js
mount() {
  const fragment = this.source.html.cloneNode(true)
  this.container.replaceChildren(fragment)

  const head = this.container.querySelector('micro-app-head')
  if (head) {
    appendStyles(head, this.source)
  }

  runScripts(this)
}
```

挂载顺序：

```txt
插入 DOM
  -> 插入 CSS
  -> 执行 JavaScript
  -> 子应用框架渲染页面
```

加载器负责准备运行环境，Vue 或 React 的入口脚本负责创建框架实例并渲染业务内容。

## 10. 加载器事件

加载器可以在关键阶段向主应用派发事件：

```txt
created     -> 开始加载
beforemount -> 资源准备完成
mounted     -> 渲染完成
unmount     -> 已卸载
error       -> 加载失败
```

```js
function createLifeCycleEvent(name, app, extraDetail = {}) {
  return new CustomEvent(name, {
    bubbles: false,
    detail: {
      name: app.name,
      url: app.url,
      baseurl: app.baseurl,
      ...extraDetail,
    },
  });
}
```

主应用监听事件：

```vue
<micro-app
  @created="recordEvent('开始加载', $event)"
  @beforemount="recordEvent('资源就绪', $event)"
  @mounted="recordEvent('渲染完成', $event)"
  @unmount="recordEvent('已卸载', $event)"
  @error="recordEvent('加载失败', $event)"
/>
```

Vue 的 `@mounted` 最终会转换成 DOM 事件监听。加载器调用 `dispatchEvent()` 后，对应监听器被触发。

这些事件是加载器对主应用发出的状态通知，不是要求子应用导出的生命周期函数。

## 11. Vue 和 React 子应用

子应用仍然保留普通框架入口：

```html
<div id="app"></div>
<script type="module" src="/src/main.js"></script>
```

加载器执行入口脚本后，子应用自己创建 Vue 或 React 实例。

```js
const container =
  window.__MICRO_APP_CONTAINER__?.querySelector("#app") ||
  document.querySelector("#app");

createApp(App).use(router).mount(container);
```

React 的挂载方式相同，只是使用 `createRoot(container)`。

类 MicroApp 通过执行普通应用入口完成渲染，不要求子应用像 qiankun 一样导出：

```js
export async function bootstrap() {}
export async function mount() {}
export async function unmount() {}
```

```txt
qiankun
  -> 主应用调用子应用导出的生命周期

类 MicroApp
  -> Custom Element 生命周期启动加载器
  -> 加载器执行子应用原有入口
```

加载器内部的 `mount()`、`unmount()` 与子应用导出的生命周期不是同一概念。

## 12. 路由基座

子应用独立运行时可能使用：

```txt
/list
/exceptions
```

嵌入主应用后，需要挂在主应用分配的路径下：

```txt
/micro/order/list
/micro/order/exceptions
```

加载器将 `baseurl` 注入子应用：

```js
window.__MICRO_APP_BASE_URL__ = app.baseurl;
```

Vue Router：

```js
const router = createRouter({
  history: createWebHistory(baseurl),
  routes,
});
```

React Router：

```jsx
<Router basename={baseurl}>
  <App />
</Router>
```

子应用管理业务域内部路由，主应用通过路由前缀识别并激活对应子应用。

`__MICRO_APP_BASE_URL__` 是手写案例的教学变量，不是 MicroApp 官方固定接口。真实 MicroApp 使用 `baseroute` 和自身的虚拟路由机制，子应用可读取 `window.__MICRO_APP_BASE_ROUTE__`。

## 13. 元素作用域

主应用和子应用可能都包含：

```html
<div id="app"></div>
```

子应用直接执行：

```js
document.querySelector("#app");
```

可能得到主应用的根节点。加载器需要让子应用优先查询自己的容器：

```js
const target =
  container.querySelector("#app") || document.querySelector("#app");
```

轻量元素作用域可以代理：

- `document.querySelector()`
- `document.querySelectorAll()`
- `document.getElementById()`
- `document.head`
- `document.body`

核心原则：

```txt
子应用查询 DOM 时，先查当前 micro-app 容器
```

真实框架还需要处理原型链方法、动态元素、弹窗容器和更多 DOM API。

## 14. Module 脚本

Vite 开发态入口通常是：

```html
<script type="module" src="/src/main.js"></script>
```

Classic Script 可以使用 `new Function()` 配合代理 `window` 执行。Module Script 由浏览器模块系统处理，不能用相同方式包装。

手写加载器采用：

```txt
注入子应用名称、容器和路由基座
  -> 使用 import() 加载入口模块
```

### 14.1 模块缓存

动态导入同一个 URL 时，浏览器通常复用已执行的模块。子应用卸载后再次进入，如果入口模块没有重新执行，容器会保持空白。

手写加载器为入口追加加载标识：

```txt
?__micro_app_entry__=<loadId>
```

每次加载使用不同 URL，从而重新执行入口模块。这是教学实现，不是 MicroApp 官方固定方案。

真实 MicroApp 对 Vite 原生 ESM 通常建议使用 iframe 沙箱：

```html
<micro-app name="finance" url="http://localhost:5175/" iframe></micro-app>
```

框架开发态插件可能注入额外脚本或假设自己运行在顶层页面，HTML Entry 加载时需要检查这些行为。

## 15. 简化样式隔离

手写加载器给普通选择器增加容器前缀：

```css
.order-card {
  color: red;
}
```

转换为：

```css
micro-app[name="order"] .order-card {
  color: red;
}
```

这样可以减少子应用普通样式向外污染。

不能直接按普通选择器处理：

- `html`、`body`、`:root`
- `@font-face`
- `@keyframes`
- 运行时插入的 `<style>`、`<link>` 和 CSSOM 规则

主应用中的全局选择器也可能向下影响子应用：

```css
button {
  font-size: 12px;
}

* {
  box-sizing: border-box;
}
```

工程规范仍然需要限制全局选择器，并为类名、字体名和动画名增加明确前缀。框架可以减少样式冲突，不能完全替代 CSS 边界管理。

## 16. JavaScript 沙箱

简化实现可以通过 `Proxy`、代理 `window` 和 `document` 为 Classic Script 提供受控环境：

```txt
子应用 JavaScript
  -> proxyWindow
  -> 受控的全局读写和 DOM 查询
```

沙箱主要处理：

- 全局变量冲突
- 全局事件和定时器残留
- DOM 查询越界
- 子应用卸载后的副作用清理

手写版本只展示方向，不具备完整沙箱能力。

## 17. 通信、预加载与错误处理

### 17.1 通信

MicroApp 的通信围绕具体 `<micro-app>` 实例建立，主应用可以向子应用传递数据，子应用也可以向主应用发送消息。

```txt
qiankun  -> 偏全局状态模型
MicroApp -> 偏实例绑定的组件通信模型
```

### 17.2 预加载

预加载在正式挂载前获取 HTML、CSS 和 JavaScript。用户进入子应用时可以直接使用缓存资源。

### 17.3 错误处理

错误可能发生在：

- HTML 请求
- CSS 请求
- JavaScript 请求
- JavaScript 执行
- 框架挂载

加载器应将状态转换为 loading、mounted 或 error，并向主应用发送事件。

## 19. 核心结论

1. `<micro-app>` 是通过 Custom Elements 注册的自定义标签，不是浏览器原生标签。
2. 标签插入页面后，`connectedCallback()` 触发子应用加载。
3. HTML Entry 负责获取入口 HTML，并接管 DOM、CSS 和 JavaScript 资源处理。
4. 加载器准备容器和运行环境，Vue 或 React 入口脚本负责渲染业务页面。
5. 类 MicroApp 通过标签生命周期控制加载，不要求子应用导出 qiankun 生命周期。
6. 框架子应用需要处理路由基座、挂载容器、Module Script 和模块缓存。
7. 元素作用域、样式隔离和 JavaScript 沙箱分别限制 DOM、CSS 和全局副作用。
8. 真实 MicroApp 还需要通信、预加载、缓存、路由隔离和错误兜底。
9. 手写加载器用于说明关键机制，不等同于 MicroApp 官方源码实现。
